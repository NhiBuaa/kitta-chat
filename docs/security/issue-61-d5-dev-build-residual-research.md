## Compatibility/build surface

The client build uses Vite, PostCSS, Rollup, Tailwind, autoprefixer, and the Node-polyfills plugin. A focused tranche must verify `npm run build`, lint, and existing client tests; Vite 8 and ESLint 10 are major-version choices and should not be folded into a patch-floor update. Docker uses `node:22-alpine`; Vite 8's published engine floor requires Node `>=22.12.0`, so the exact CI/deployed Node 22 minor must be confirmed before selecting Vite 8. No source migration is evidenced for the patch-floor path (`vite >=7.3.5`, `postcss >=8.5.23`, `rollup >=4.59.0`, `nanoid >=3.3.17`, brace-expansion safe branch).

## Uncertainties and failure state

- `node:22-alpine` is a moving image tag; repository evidence does not pin its Node minor. This blocks choosing Vite 8 as the smallest safe target, not the Vite 7.3.5 patch-floor path.
- npm audit identifies package ranges and available fixes, but does not prove exploitability through this application's inputs. The classifications above are reachability classifications, not risk acceptance.
- No failure state was encountered in read-only inspection. No mutation was attempted.

## D5 disposition gate

Recommended smallest future mutation tranche: client build/tooling patch floors (`vite >=7.3.5`, `postcss >=8.5.23`, `rollup >=4.59.0`, `nanoid >=3.3.17`) plus the `styled-components` parent cleanup that removes its nested vulnerable PostCSS, with focused build/lint/client-test verification. Handle root/server license-checker and server test-only Socket.IO cleanup separately. Keep ESLint, client Socket.IO/Engine.IO, and any other no-finding paths retained pending explicit disposition.

Failure state: **none**. This note is evidence only; D5 mutation remains a human decision gate.
